# Engineering & Security Rules — Vult

**Product**: Vult  
**Version**: 1.0.0 Stable Baseline $\rightarrow$ 2.0.0 Roadmap  
**Author**: Kurados  

---

## 1. Core Mission & Immutable Principles

1. **Zero-Cloud, Zero-Telemetry Mandate**:
   - Vult must NEVER make outbound HTTP, HTTPS, WebSocket, or UDP network requests to third-party cloud servers or analytics endpoints.
   - Any proposed feature that requires a cloud intermediary or proprietary relay server is rejected by design.
   - The application Content Security Policy (`CSP`) must strictly deny external scripts, styles, or telemetry:
     ```json
     "csp": "default-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; font-src 'self' data:; img-src 'self' data: https:;"
     ```

2. **Absolute Data Sovereignty**:
   - The user's encryption key and decrypted vault data must exist only in volatile local memory (RAM) while unlocked, and in an AES-256-GCM encrypted file on local disk while locked.
   - Master passwords and PINs must NEVER be written to disk in plaintext, logged, or serialized into persistent state.

3. **Compact Native Desktop Footprint**:
   - Window size must remain strictly locked to **400 × 620 pixels** (`resizable: false`, `maximizable: false`).
   - The app must behave as an agile, compact companion tool that floats neatly beside browser or IDE windows.
   - Clicking window close ($\times$) must exit the process completely unless explicitly instructed otherwise (no zombie background tray processes).

---

## 2. Cryptographic Security Standards

1. **Key Derivation (Argon2id)**:
   - Always use `Argon2id` (hybrid of Argon2d and Argon2i) to guard against both side-channel cache attacks and GPU/ASIC brute-force attacks.
   - Memory cost must not be lowered below $64\text{ MiB}$ ($65,536\text{ KiB}$) for release builds.
   - Iteration count must be at least $3$ passes with parallelism set to $4$ threads.

2. **Authenticated Symmetric Encryption (AES-256-GCM)**:
   - Every encryption operation must generate a fresh, cryptographically secure 96-bit (12-byte) random initialization vector / nonce using `rand::rngs::OsRng`. Nonce reuse is strictly forbidden.
   - The Additional Authenticated Data (`AAD`) must bind the payload header (magic bytes, version, parameters) to the ciphertext.

3. **Memory Hygiene & Zeroization**:
   - All secret structs, byte vectors containing decrypted data, and derived master keys must implement `zeroize::Zeroize` and `zeroize::ZeroizeOnDrop`.
   - On vault lock, logout, or panic, all decrypted buffers in memory must be overwritten with zeroes.

4. **Brute-Force Lockout Defense**:
   - Failed unlock attempts must trigger exponential backoff delays ($1\text{s}$, $2\text{s}$, $4\text{s}$, $8\text{s}$, up to $30\text{s}$) managed by the Rust backend to render local automated dictionary attacks unviable.

## 3. Frontend & UI/UX Standards

1. **Zero Browser Native Prompts**:
   - Never use `window.alert()`, `window.confirm()`, or `window.prompt()`. Chromium's default popups (`127.0.0.1 says...`) shatter desktop app aesthetics.
   - All prompts, confirmations, and credential inputs must use in-DOM custom modal dialogs (`src/js/components/modal.js`) styled with macOS-inspired dark frosted glass (`backdrop-filter: blur(8px)`).

2. **Universal Web-Safe Symbols in Password Generator**:
   - Passwords generated by the app must strictly use characters accepted by standard web forms:
     ```javascript
     let syms = "!@#$%^&*()-_=+";
     ```
   - Characters like pipes (`|`), brackets (`[ ] { }`), colons (`:`), semicolons (`;`), commas (`,`), and angle brackets (`< >`) must remain excluded from default symbol generation because they trigger validation rejections across banking, enterprise, and cloud services.

3. **Keyboard Accessibility & Ergonomics**:
   - Modal forms must support intuitive keyboard navigation:
     - <kbd>Enter</kbd> moves from the primary input to the confirmation input, and from the confirmation input to submit.
     - <kbd>Esc</kbd> closes non-destructive modals and cancels pending actions.
   - PIN input fields must automatically filter out non-digit keystrokes in real time (`replace(/\D/g, "")`).

---

## 4. Rust Backend Standards

1. **Strict Error Propagation**:
   - Never use `.unwrap()` or `.expect()` in production IPC command pathways. Errors must map into human-readable strings or structured error types returned to the frontend via `Result<T, String>`.

2. **Atomic Filesystem Writes**:
   - When writing `vault.vult`, write to a temporary file in the same directory (`vault.vult.tmp`) first, flush to disk with `sync_all()`, and then perform an atomic rename/replace. This guarantees that an unexpected power outage or crash cannot corrupt the user's vault database.
   - Maintain a rolling backup file (`vault.vult.bak`) updated before any destructive write.

---

## 5. Git Governance & Version Branching

1. **Branching Model**:
   - `main`: Active development branch for validated features.
   - `v1.0.0-stable`: Permanent frozen backup branch of the v1.0.0 production baseline.
   - Release tags follow Semantic Versioning (`vX.Y.Z`).

2. **Quality Gates Before Commit**:
   - 100% of Rust backend unit and integration tests must pass: `cargo test` in `src-tauri`.
   - 100% of JavaScript automated suites must pass: `node tests/test-code-detector.mjs`.
   - Working tree must be verified clean before pushing to remote repository.
